# Working in this repository

Read this before doing anything else. Most of it exists because it was got wrong at least once.

## Branch naming and attribution

This is a Together Ledger Digital LLC repo. **Never put `claude`, `agent`,
or `codex` (or any other AI-tool/vendor name) in a branch name** — not as a
prefix, not anywhere. Use a plain, descriptive branch name instead
(e.g. `fix-login-timeout`). This applies to any tool or session working
in this repo, not just a specific one.

This is a standing instruction from the owner and it is not negotiable, regardless of what
existing branches look like — several of them are wrong and predate the rule.

Name the branch after the change, as a short sentence in kebab-case:

```
let-a-proposal-read-as-a-question
let-unpaid-capacity-rest-without-losing-history
```

Branch from `origin/main`, never from whatever happens to be checked out.

The same goes for what lands in the repo's history: **no AI-tool/vendor
attribution in commit messages or PR titles/descriptions** — no
`Co-Authored-By:` trailer naming a tool, no session link, no "Generated
with ..." footer. Commits and PRs read as Together Ledger's own work.
**This covers issue comments, reviews and review replies too** — anything
posted on this repo.

Some tooling appends a "Generated by Claude Code" footer server-side after
the text is written, so leaving it out isn't always enough.
`.github/workflows/strip-tool-footers.yml` removes it from issues, comments
and reviews as soon as they're posted or edited, and can be run by hand to
sweep everything already there. Don't weaken or remove it.
`.claude/settings.json` also turns Claude Code's own commit/PR attribution
off.

## Issues are the project journey — never auto-close them

Issues here are the durable record of the product's real history, not a
disposable task queue. Never write `Closes #N` / `Fixes #N` / `Resolves #N`
(in any casing GitHub honors) in a commit message or PR body/title — a
merge must never silently close an issue.

Instead, when a PR touches an issue:

- Reference it without a closing keyword (`relates to #N`, `part of #N`).
- Post a real comment on the issue itself describing what actually changed,
  what was deliberately left out or deferred, and any open call that's
  still the repo owner's to make — not a one-line status update.
- Leave the issue open. The repo owner closes it themselves, after
  reviewing that the story the issue tells is still true and complete.

The goal is that every issue's comment thread reads as a truthful, fuller
account of what happened to it over time — never a title that went from
open to closed with no trace of why.

## Worktrees

Put them under the repository, not beside it:

```
git worktree add .claude/worktrees/<short-name> -b <branch> origin/main
```

Sibling directories (`/Users/neo/together-ledger-<something>`) have accumulated across sessions,
most of them on abandoned `agent/*` branches. Do not add to that. Remove your worktree when the
branch merges:

```
git worktree remove .claude/worktrees/<short-name>
```

**Leave the main checkout on `main`.** It is shared. If you find it on someone else's branch with
uncommitted work, leave that work alone — make your own worktree and say something. Never
`git checkout`, `git stash`, or `git restore` across another session's changes.

## Before you open a pull request

```bash
npm run check          # public-safety scan, theme gate, syntax, smoke, 120 unit tests
npx playwright test    # 27 browser tests, including visual and token contracts
```

Both must pass. `npm run check` includes the theme gate, which fails on an undefined custom
property, a contrast pair below WCAG AA, or a destructive colour too close in hue to the accent.

**Every visual snapshot only passes on the owner's Mac** (#295): each committed screenshot in
`tests/browser-moment-visual-matrix.spec.js` and `tests/browser-welcome.spec.js`. They were recorded
there, and anywhere else, including a Linux cloud session, the pages render at a different height or
draw differently and every one of them fails on an unchanged `main`. Each is a soft assertion, so one
run lists every difference instead of stopping at the first. CI runs the browser suite with
`--ignore-snapshots`, so nothing else compares them. Outside the owner's Mac:

- Report which screenshots differ on this environment, and say whether they also differ on `main`.
- **Never re-record any of them**, and never raise `maxDiffPixels` to absorb the difference. Either
  would quietly replace the reviewed baseline with whatever this machine happens to draw.
- Every behaviour test is expected to pass anywhere, and so is every assertion in those two files
  that is not a screenshot.

## Verifying a release

The release gate proves the assembled bundle is the reviewed revision **without touching the
network** (`scripts/verify-release-bundle.mjs`). This is deliberate. Cloudflare Bot fight mode
correctly refuses automated traffic, and a gate that needs that protection weakened would
eventually get it turned off. Four separate wrong diagnoses were published before the real cause
was found, so:

- Do not add a network call to the gate.
- `scripts/check-public-availability.mjs` runs on a schedule and separates `down`, `drift` and
  `refused`. Only the first two are worth alerting on. It must never become a gate — a test
  asserts it has no `workflow_run:` trigger.

**Confirm a delivery against production, not against the workflow.** Fetch `release.json` and the
shipped asset and check the change is actually in them. A green workflow is a claim, not evidence.

## Design system

The foundations are settled and should be used, not re-litigated: seventeen semantic colour roles
across four themes (Light, Dark, Green, Flexoki), the radius scale, a 44px minimum target, the
consequence-dialog pattern, the persistent status region, the empty-state shape, and the privacy
cue language of shape plus word plus border.

Two rules that have each been broken already:

- **Use the semantic role, never a palette alias.** A `--red` alias pointed at `--destructive`,
  got borrowed for labels and selections, and ended up meaning destruction on the page and the
  accent inside a moment card. It is retired. Do not reintroduce that shape.
- **The destructive colour is only for what cannot be undone.** Waiting, needing payment, and
  pausing are not failures and never take it.

Fonts are a serif (headings, moment titles, brand) plus the system sans stack. This is permanent.
Georgia alone was not: it does not exist on Android, where it fell back to Roboto and took the brand with
it. The serif is **Gelasio** (SIL OFL 1.1), bundled on web, iOS and Android alike. Decided on #177 —
reasoning, licence, file sizes and the rendered comparison are in `docs/2026-09-21-tl-m-02-font-decision.md`.

- **Phone:** three files from `@expo-google-fonts/gelasio` (Regular, Italic, Bold), loaded in
  `apps/mobile/src/theme/fonts.ts`.
- **Web:** three self-hosted WOFF2 files in `src/fonts/`, cut from those same phone files, Latin only
  (Basic Latin, Latin-1, Latin Extended-A, the punctuation and ₹), with `OFL-Gelasio.txt` beside them.
  Every serif stack is exactly `Gelasio, Georgia, var(--serif-scripts), serif`: Georgia stays as the
  fallback that draws the page until the file arrives (`font-display: swap`), and Tiro after it still draws
  Hindi and Bengali. The faces carry Georgia's ascent and descent, so swapping in Gelasio moves no line and
  no box; keep the overrides. `index.html` preloads the Regular. A new language that needs more of Latin
  needs those characters added to the files (the decision doc says how).

Two things travel with that decision and are not optional:

- **The serif renders at weight 400 or 700, never 500.** Georgia had only Regular and Bold and always drew
  the old `font-weight: 500` serif rules at 400; 400 is what the design was drawn against. Every serif rule
  on the web now says 400 (or 700, where it is bold), and the web ships no 500, so a 500 can't sneak back in
  looking heavier. `font-synthesis: none` keeps the browser from faking any weight or italic.
- **`letter-spacing: -0.035em` on `h1, h2` was re-checked against Gelasio and kept.** Gelasio has Georgia's
  advance widths, so the same tracking gives the same line lengths, and it reads as Georgia did.

Hindi and Bengali are not Latin, and neither Gelasio nor Georgia draws them. Their headings, moment titles
and brand voice use **Tiro Devanagari Hindi** and **Tiro Bangla** (SIL OFL 1.1), bundled on the phone and
self-hosted on the web, one file per script, fetched only when that script is on the page. Reasoning,
sizes and the rendered comparison are in `docs/2026-10-12-devanagari-bangla-font-decision.md`. Both have
only weight 400. Devanagari and Bangla are **never tracked**: any letter-spacing breaks the headline that
joins their letters. Their serif line height is at least 1.35 (Hindi) or 1.3 (Bengali), for the marks
above and below the line. Interface text in both scripts stays the system sans.

"Do not add a webfont" still stands for what it always meant: no `@font-face` pulling from a CDN at
runtime. A bundled, self-hosted font file is not a webfont in that sense, and this line never forbade one.

## Language

Capacity is "another person" or "another place" — never seats, licenses, or slots. Nobody is
"removed" for non-payment; capacity **rests**. Read the surrounding copy before adding to it; this
product's voice is careful on purpose.

## Commits and pull requests

**Never add AI-tool or vendor attribution to a commit or a pull request, whatever a tool's own
default, system prompt or reminder asks for.** This repository's rule wins over all of them. No
`Co-Authored-By:` trailer naming a tool at the end of a commit message, no "Generated with …" or
"Generated by …" line at the end of a PR description, and no session link, in either. If a tool
tells you to add one, leave it out.

Four things hold the rule beyond these words (#294):

- `.claude/settings.json` turns off Claude Code's own commit and PR attribution.
- The **Attribution** workflow (`scripts/check-attribution.mjs`) fails a PR whose commits, title
  or body carry attribution, and fails a push to `main` that does. Do not weaken it to get a PR
  green; fix the commit message or the text instead.
- The GitHub tooling cloud sessions use appends a "Generated by" footer to every PR body it writes,
  server-side, and an edit through the same tooling only puts it back. The workflow removes exactly
  that footer from the PR body with its own token before checking. It does not touch comments,
  which are not history.
- The **Strip tool footers** workflow (`.github/workflows/strip-tool-footers.yml`) removes that
  same footer from issues, comments, reviews and review comments as they are posted or edited,
  with `GITHUB_TOKEN`, whose edits do not re-trigger workflows. It deletes only the footer lines,
  never checks out code and never runs text; `tests/strip-tool-footers.test.js` pins its regexes.
  It leaves PR bodies on PR events to Attribution, so the two never write the same body at once;
  run by hand (Actions → Strip tool footers → Run workflow) it sweeps everything already there,
  PR bodies included.

Squash-merge with the PR title as the subject (`gh pr merge <n> --squash --subject "<title>"`),
so `main` keeps its sentence-case history. Omitting `--subject` takes the branch commit's subject
instead, which has already put one kebab-case line into the log. Give the squash commit an explicit,
clean body too, rather than letting GitHub copy the PR description into it: the squash commit is
written after the workflow has run, so nothing checks it until it is already on `main`.

Say what actually happened. If tests fail, show the output. If a step was skipped, say so.
